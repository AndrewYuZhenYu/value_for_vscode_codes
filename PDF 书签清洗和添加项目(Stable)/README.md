# PDF 书签清洗与智能添加工具

一个基于 **PyMuPDF (fitz)** 的 PDF 目录（书签）批量写入工具。它从外部 Markdown / TXT 文件中读取层级化目录数据，自动叠加页码偏移量，写入 PDF 书签，并**注入双重逻辑页码**（前言用罗马数字、正文用阿拉伯数字），让阅读器侧边栏与实际书页页码完全对应。

## 一、面向用户

### 1.1 程序能做什么

很多扫描版、OCR 版或电子书 PDF 存在以下问题：

- 没有书签目录，或者原有书签错乱、需要全部替换；
- 书上的印刷页码和 PDF 阅读器里的物理页码对不上（比如封面、前言、目录占了 10 页，正文第 1 页在 PDF 里其实是第 11 页）；
- 阅读器底部的页码显示和书上页码完全脱节，翻页时无法靠页码定位。

本程序一次性解决上述三个问题：

1. **清除原有目录**，用你提供的目录文件重建完整书签树；
2. **自动叠加页码偏移量**（`物理页码 = 书面页码 + OFFSET`），让书签点击后精准跳到目标页；
3. **注入双重逻辑页码**：
   - 前言部分（封面、序、目录等）显示为**罗马数字** `i, ii, iii...`；
   - 正文部分显示为**阿拉伯数字** `1, 2, 3...`，与书上印刷页码一致。
4. 保留原 PDF 内容不变，输出为一个新文件。

### 1.2 环境准备

**系统要求：**

- Windows / macOS / Linux 均可
- 已安装 Python 3.8 及以上版本

**安装依赖：**

```bash
pip install pymupdf
```

> `fitz` 是 PyMuPDF 的旧称，现在统一通过 `pip install pymupdf` 安装，导入时仍写作 `import fitz`。

### 1.3 配置说明

所有可调参数集中在文件顶部的 `CONFIG` 字典里，**日常使用只需改这一处**：

```python
CONFIG = {
    "TOC_FILE":   ".../离散数学目录文件.md",   # 目录文件路径
    "INPUT_PDF":  ".../离散数学（第2版）（MACOCR）.pdf",  # 原始 PDF
    "OUTPUT_PDF": ".../离散数学最终版本新程序测试.pdf",   # 输出 PDF
    "OFFSET":     10,                          # 页码偏移量
}
```

| 字段         | 含义         | 说明                                        |
| ------------ | ------------ | ------------------------------------------- |
| `TOC_FILE`   | 目录内容文件 | 支持 `.txt` / `.md`，格式见下一节           |
| `INPUT_PDF`  | 待处理 PDF   | 程序不会修改它，只读取                      |
| `OUTPUT_PDF` | 输出 PDF     | 若同名文件已存在会被覆盖                    |
| `OFFSET`     | 页码偏移量   | `物理页码 = 书面页码 + OFFSET`，从 0 开始算 |

> **OFFSET 如何确定？**
> 在 PDF 阅读器里找到正文第 1 页，看它实际是第几页。比如正文第 1 页显示为阅读器第 11 页，那么 `OFFSET = 11 - 1 = 10`。
> 若整本没有前言、书页与物理页一一对应，则设为 `0`。

### 1.4 目录文件格式

目录文件每行一条书签，用竖线 `|` 分隔三个字段：

```
层级 | 标题 | 书面页码
```

**规则说明：**

- `层级`：整数，通常 1 表示章、2 表示节、3 表示小节（取决于 PDF 阅读器，一般 1~6）；
- `标题`：书签显示的文字；
- `书面页码`：书上印刷的页码（**不是** PDF 物理页码，程序会自动加 OFFSET）；
- 以 `#` 开头的行视为注释，会被忽略；
- 空行会被忽略；
- 格式错误的行会打印警告并跳过，不影响其他行。

**示例：**

```
# 离散数学目录文件
1 | 第1章 命题逻辑 | 1
2 | 1.1 命题与联结词 | 1
2 | 1.2 命题公式与分类 | 8
1 | 第2章 一阶逻辑 | 31
2 | 2.1 一阶逻辑基本概念 | 31
3 | 2.1.1 个体词与谓词 | 32
```

### 1.5 使用方法

1. 安装依赖（见 1.2）；
2. 打开 `整合重构最新版本.py`，修改 `CONFIG` 中的四个路径与偏移量；
3. 运行：

```bash
python 整合重构最新版本.py
```

4. 控制台会打印解析进度、书签条数、Page Labels 注入结果，最终输出新 PDF。

**典型输出：**

```

正在打开 PDF 文件...
正在清除原有的目录...
准备写入 128 条新目录...
正在设置双重逻辑页码 (Page Labels)...
✅ 逻辑页码规则注入成功: 前言 [0 ~ 9] -> 罗马数字, 正文 [10 ~ 结尾] -> 阿拉伯数字 1 起始
正在保存新的 PDF 到: '离散数学最终版本新程序测试.pdf'

```

### 1.6 常见问题

**Q1：运行后书签点击跳错页？**

- 多半是 `OFFSET` 设置不对。重新确认正文第 1 页的物理页码，用 `OFFSET = 物理页 - 书面页` 计算。

**Q2：书签层级显示不对（全部平铺或缩进错乱）？**

- 检查目录文件里的层级数字是否从 1 开始、是否跳跃过大。一般阅读器要求层级连续递增。

**Q3：阅读器底部页码没变化？**

- Page Labels 是 PDF 标准特性，Adobe Acrobat、Foxit、macOS 预览、部分浏览器内置阅读器支持；某些简易阅读器可能忽略该特性，这属于阅读器兼容性问题。

**Q4：目录文件里有些行没生效？**

- 查看控制台警告，通常是缺少 `|` 分隔符，或页码位置写成了非数字。

**Q5：原文书签丢失了怎么办？**

- 程序会执行 `doc.set_toc([])` 主动清空旧书签，属于设计行为。若想保留旧书签，请先备份原 PDF。

## 二、面向开发者

### 2.1 技术栈

| 组件                 | 作用                                      |
| -------------------- | ----------------------------------------- |
| **Python 3**         | 主语言                                    |
| **PyMuPDF (`fitz`)** | 打开/保存 PDF、读写 TOC、设置 Page Labels |
| **os**               | 路径存在性校验                            |

选型理由：

- PyMuPDF 是纯 C 内核绑定的 PDF 库，读写 TOC 和 Page Labels 是一等公民 API，无需借助其他工具；
- `set_toc` 与 `set_page_labels` 均为原生方法，稳定且无损。

### 2.2 整体架构

程序是**单文件、配置驱动**的脚本，采用"配置区 + 纯函数 + 入口调用"三段式结构：

```
┌─────────────────────────────────────────────┐
│  1. 配置层   CONFIG 字典集中管理四项参数       │
├─────────────────────────────────────────────┤
│  2. 解析层   逐行读取目录文件 → 校验 → 结构化   │
│     - 跳空行/注释；split('|')；int 转换        │
│     - 叠加 OFFSET 得到物理页码                 │
├─────────────────────────────────────────────┤
│  3. 写入层   fitz.open → set_toc([]) → set_toc │
│     - 清空旧书签，写入新书签树                 │
├─────────────────────────────────────────────┤
│  4. 页码层   set_page_labels 注入双重逻辑页码 │
│     - 前言罗马数字 + 正文阿拉伯数字            │
├─────────────────────────────────────────────┤
│  5. 保存层   doc.save(output_pdf) → close     │
└─────────────────────────────────────────────┘
```

设计上刻意把"配置"与"逻辑"解耦：函数 `update_pdf_toc_from_file` 完全无副作用地接收四个参数，未来若要做 CLI 或批处理，只需换入口，不动核心逻辑。

### 2.3 核心实现原理

**① 目录文件解析与容错**

```python
for line_num, line in enumerate(f, 1):
    line = line.strip()
    if not line or line.startswith('#'):
        continue
    parts = line.split('|')
    if len(parts) == 3:
        try:
            level = int(parts[0].strip())
            title = parts[1].strip()
            book_page = int(parts[2].strip())
            if book_page < 1:
                continue
            actual_page = book_page + offset
            new_toc.append([level, title, actual_page])
        except ValueError:
            print(f"⚠️ 警告: 第 {line_num} 行格式错误...")
    else:
        print(f"⚠️ 警告: 第 {line_num} 行格式不匹配...")
```

- `enumerate(f, 1)` 让行号从 1 开始，方便报错定位；
- 分隔符选择 `|` 而非空格或制表符，避免标题中含空格时被误切；
- 对每行做**两重校验**：字段数是否为 3、数字字段能否 `int()` 转换；
- 单行出错只跳过该行，不中断整体流程——这是批处理工具的基本鲁棒性要求。

**② 页码偏移与书签构建**

```
actual_page = book_page + offset
new_toc.append([level, title, actual_page])
```

PyMuPDF 的 TOC 数据结构是 `[[level, title, page], ...]`：

- `level`：整数层级（1 起）；
- `title`：书签文本；
- `page`：**从 1 开始的物理页码**（PyMuPDF 内部会转换为 0-based 存储）。

因此书签和 Page Labels 的数学关系是：

- 书签指向 `book_page + offset`；
- 阅读器跳转后显示的页码，正是 Page Labels 中正文段的 `book_page`。

两者对齐后，用户体验即为"点书签 → 跳到正确页 → 底部页码与书上一致"。

**③ 清空并重建 TOC**

```python
doc.set_toc([])
doc.set_toc(new_toc)
```

- 先传空列表清空原有书签，避免新旧混合；
- 再一次性写入新列表，PyMuPDF 会自动构建层级树。

**④ 双重逻辑页码 (Page Labels)**

```python
page_labels = []
if offset > 0:
    page_labels.append({"startpage": 0, "style": "r", "prefix": "", "start": 1})
    page_labels.append({"startpage": offset, "style": "D", "prefix": "", "start": 1})
else:
    page_labels.append({"startpage": 0, "style": "D", "prefix": "", "start": 1})
doc.set_page_labels(page_labels)
```

Page Labels 是 PDF 规范（ISO 32000）中的标准特性，阅读器侧边栏/底部会按它显示页码。每条规则字段含义：

| 字段        | 含义                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| `startpage` | 规则生效的**起始物理页（0-based）**                                              |
| `style`     | 编号样式：`D`=阿拉伯数字，`r`=小写罗马，`R`=大写罗马，`A`=大写字母，`a`=小写字母 |
| `prefix`    | 页码前缀（如 `A-`）                                                              |
| `start`     | 起始序号                                                                         |

本程序的策略：

- `startpage=0` 段用 `r` 样式，覆盖封面/前言，显示 `i, ii, iii...`；
- `startpage=offset` 段用 `D` 样式，从 1 重新计数，覆盖正文；
- 若 `offset == 0`（无前言），直接整本用 `D`。

这是一个**分段编号**方案，等价于 LaTeX 的 `\frontmatter` / `\mainmatter`。

**⑤ 资源安全**

```python
try:
    doc = fitz.open(input_pdf)
    ...
finally:
    doc.close()
```

- 打开失败立即返回，避免对 `None` 调用方法；
- 保存放在 `try`，`close` 放在 `finally`，保证文件句柄一定被释放。

### 2.4 关键代码解析

| 变量 / API                 | 作用         | 调优建议                                |
| -------------------------- | ------------ | --------------------------------------- | ---------- | ----------------------- |
| `CONFIG` 字典              | 集中配置     | 未来可换成 YAML/JSON/argparse           |
| `line.split('              | ')`          | 字段切分                                | 若标题含 ` | `，需换更复杂分隔或转义 |
| `book_page + offset`       | 页码映射     | offset 可为负（前言倒挂场景）           |
| `doc.set_toc([])`          | 清空书签     | 想保留旧书签需先 `doc.get_toc()` 再拼接 |
| `doc.set_page_labels(...)` | 注入逻辑页码 | `style` 可换 `R`/`A`/`a`                |
| `doc.save(output_pdf)`     | 保存         | 可加 `garbage=4, deflate=True` 压缩体积 |

**关于 `set_page_labels` 的兼容性：**

- 若 `offset` 超过 PDF 实际页数，正文段规则会被忽略或报错，建议加边界检查；
- 若 PDF 本身已有 Page Labels，本程序会整体覆盖。

### 2.6 可扩展方向

1. **CLI 化**：用 `argparse` 把 `CONFIG` 四项变成命令行参数，支持脚本批量调用；
2. **批量处理**：遍历目录下所有 PDF，自动匹配同名 `.md` 目录文件；
3. **自动推断 OFFSET**：通过书签与正文页脚 OCR 对照，自动计算偏移量；
4. **保留旧书签**：提供 `MERGE` 模式，将新书签追加到原有书签之后；
5. **规则文件校验器**：独立脚本预先检查目录文件的层级连续性与页码单调性；
6. **多段 Page Labels**：支持"封面-前言-目录-正文-附录-索引"多段不同编号体系；
7. **PDF 元数据**：顺手写入标题、作者、关键词等 `doc.set_metadata`；
8. **体积优化**：`doc.save(..., garbage=4, deflate=True, clean=True)` 去除冗余对象。
