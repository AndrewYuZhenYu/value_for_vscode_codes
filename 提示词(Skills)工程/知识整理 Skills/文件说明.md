# 知识整理 Skill 版本对比说明

| 版本 | 优点                                     | 缺点                                 |
| ---- | ---------------------------------------- | ------------------------------------ |
| 2.0  | 规则全面，具体约束多，检查清单完整       | 冗长重复，元讨论多，模型易注意力稀释 |
| 3.0  | 覆盖维度最全，示例丰富，设计参考价值高   | 过度膨胀，规则疲劳，执行性差         |
| 3.1  | 精简高密度，可执行性强，优先级明确       | 部分具体约束被抽象化，示例偏少       |
| 3.2  | 平衡最好，长文档机制强，资料与补充可区分 | 篇幅略增，部分补强仍偏抽象           |
| 4.0  | 最简洁，信息密度最高，执行负担最小       | 具体禁止项丢失多，长文档机制弱       |

**适用场景：**

- **2.0 / 3.0**：适合作为设计参考或规则库，用来查漏补缺、理解知识整理应考虑哪些维度。不建议直接执行，尤其 3.0 冗长重复，模型难以全程保持注意力。
- **3.1**：适合上下文中等、指令遵循较好的模型日常使用。精简后核心规则清晰，但部分具体禁止项被抽象化，需模型自行理解。
- **3.2**：当前最推荐。适合长文档、高一致性要求的任务。补强了知识地图、最小有效示例、资料与补充区分等关键点，在精简与具体约束之间平衡最好。
- **4.0**：适合上下文有限、需快速稳定输出的模型。信息密度最高，但具体约束损失较多，对模型自身理解能力要求更高，适合作为基础框架再补强。

2026.10.31 进行第一次归档操作，做一些简单的说明：
本项目最初的目的仅仅是去整理纯文字的知识点，最初的初衷主要有两点：一个是让模型全面完善细致地整理所有的知识点，另外一个是确保生成的内容能够适配 obsidian ，主要针对点是 LaTeX 公式的显示问题。以上不管是什么编号，都能满足这两点。

后来随着 chatgpt 的深入使用，发掘它的多模态生图制图能力，以及强大的文件管理能力，所以诞生了 4 代版本，四代版本主要是在三代版本的基础上对于压缩包的文件管理模式和对于 obsidian 内部链接图片等附件的语法做了规范，目的是让md 文档和图片可以分开存放，也能正常多平台显示插图，事实证明做到了，效果也很好，现在创造性的去进行命名探索，以课程名称加章节加随机数的形式基本上杜绝了文件夹或者文件重名，确保图片链接正常不冲突。

1 代和 2 代版本包括和后期主流的 3 代版本之间并没有明显的鸿沟分歧，大体一致，无非就是多了一些补充，但是和 3 代到4代之间的跨越相比要小很多，之前对于名称版本的命名不是特别规范，但是也属于历史遗留问题，也没有本质的影响，就将旧版本归置起来，无特殊情况不会再用。

最上面那些内容是对 3 代早期版本和 1，2 代版本之间的解释，其实说实话丢给大模型来写，真的没有明显差距。

目前成熟稳定的版本有两个，一个是 3.5，是纯文本时代的成熟版本。

另外一个是 4.2（或者 4.1）是插图zip 时代目前相对成熟版本。
