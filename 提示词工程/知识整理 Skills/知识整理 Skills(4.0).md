# 知识整理 Skill

## 1. 任务理解

1. 开始任务前，先理解用户的任务目标、知识主题、输入资料、处理要求、范围限制和输出格式。
2. 检查任务与资料是否匹配；若存在会实质影响结果的歧义、冲突、缺失或无法读取的问题，再进行必要确认。
3. 不要因为用户给出了明确指令，就机械执行；任务成立后再执行，执行过程中发现重大问题应及时修正。
4. 不要把普通的小问题不断反馈给用户；能够可靠判断的内容自行处理。

## 2. 知识范围

5. 用户明确指定的知识范围是最高边界；课程、教材、考试范围等构成主要范围。
6. 资料不是知识范围的唯一来源。可以补充资料中没有但对当前范围的理解和使用确有必要的知识。
7. **范围内充分展开，范围外保持克制。**
8. “全面”不等于无限扩展；不得因为知识之间存在潜在联系就无限向外扩张。

## 3. 资料处理

9. 充分读取输入资料，提取其中的知识点、定义、公式、条件、方法、例题、结论和知识关系。
10. 不机械照抄原资料的页面、章节或叙述顺序；资料混乱时，应在输出中重新组织。
11. PPT、PDF、教材、目录、笔记、图片、扫描件等不同类型资料，应根据其实际内容采取适当处理方式。
12. OCR 错误、图片模糊、公式损坏、内容缺失等无法确认的信息，不得猜测。
13. 对正确的原资料，应保留其重要定义、术语、公式、分类和课程表达；发现明显错误时应纠正，而不是机械保留错误。

## 4. 知识提取

14. 不仅提取资料中显式出现的标题和结论，还要提取其中隐含的概念、条件、前置知识、知识关系和使用逻辑。
15. 每个重要知识点都应明确其核心内容，而不是只保留标题或关键词。
16. 提取时区分核心知识、一般知识和辅助信息，避免把所有内容以相同权重堆积。

## 5. 知识补全

17. 主动发现当前知识体系中的必要缺口，包括定义、前置知识、公式、条件、方法、例子、特殊情况和知识联系。
18. 补充内容必须具有明确的知识价值，能够帮助理解、记忆、推导、计算、编程、解决问题或建立知识体系。
19. 必要补充优先；有助于理解的补充适当加入；纯扩展性内容保持克制。
20. 不得因为“我知道这个知识”就加入无关内容，也不得因为“原资料没写”就拒绝必要补充。
21. 补充内容不得伪装成原资料内容；不确定内容不得写成确定事实。

## 6. 知识组织

22. 按知识逻辑、学习顺序和前后依赖重新组织内容，而不是机械遵循原资料顺序。
23. 建立清晰的大类、子类和层级关系，但不要为了分类而强行分类。
24. 必要的前置知识应先于依赖它的知识出现；避免出现没有基础、突然跳跃的内容。
25. 不同主题采用适合其自身特点的结构，不强行套用统一模板。

## 7. 知识展开

26. 不同知识点按照重要性、复杂度和学习需要决定展开深度。
27. 简单知识点简明解释；核心知识必须达到**最低充分完整度**，使读者能够脱离原资料独立理解。
28. 核心概念根据需要说明“是什么、为什么、有什么作用、怎么用、什么时候用”。
29. 对公式、定理、方法、算法等，根据需要说明意义、条件、推导、使用方法和限制。
30. 不能为了追求整齐而让所有知识点拥有完全相同的篇幅和结构。

## 8. 例题 / 应用

31. 对需要实践才能真正理解的知识，提供适量的典型例题或应用。
32. 例题优先覆盖典型方法、直接应用、容易出错的情况和必要变式，不追求数量。
33. 重要例题应说明已知条件、目标、为什么使用该知识、解决过程和关键注意点。
34. 高度重复的题型使用代表性例题即可，不重复堆砌同一种模式。

## 9. 知识联系

35. 在确实有助于理解时建立章节、概念、方法或学科之间的联系。
36. 知识联系应服务于当前学习目标，不得为了制造“知识体系感”而强行建立联系。
37. 对存在明显依赖、对应、包含、区别或递进关系的知识，应适当明确这种关系。

## 10. 边界 / 条件 / 反例 / 易错

38. 对公式、定理、方法和结论，应在必要时明确适用条件、变量范围、前提和限制。
39. 对容易混淆或容易误用的知识，应指出典型错误和正确边界。
40. 对容易产生错误理解的概念，可以使用反例或特殊情况说明其边界。
41. 不为了形式完整而给简单知识点强行增加大量反例和特殊情况。

## 11. 去重与信息密度

42. 同一个知识点原则上只进行一次完整讲解；后续出现时采用引用、简述或联系，避免重复展开。
43. 删除重复定义、同义改写、空泛评价、无意义过渡和没有知识增量的内容。
44. **压缩表达，不压缩知识。** 不得为了变短而删除必要的定义、条件、公式、推导、例题、边界和知识关系。
45. 正文、总结、速查表承担不同功能：正文用于学习，总结用于复习，速查用于定位，不得机械复制正文。

## 12. 正确性与不确定性

46. 正确性优先于完整性。不能为了补全内容而猜测、编造或强行解释不确定信息。
47. 对公式、定义、数据、单位、代码、语法、API、复杂度、因果关系等进行必要的正确性检查。
48. 存在不同标准、定义、符号体系或有争议的内容时，应区分其适用语境，不随意混合。
49. 无法确认的内容应明确标记不确定性，而不是用确定语气掩盖不确定。

## 13. 术语 / 符号 / 表达一致性

50. 同一概念在全文中尽量使用统一的名称；首次出现时可补充英文术语或其他常用名称。
51. 同一变量、参数和数学对象尽量使用统一符号；不同资料中的符号不同，应判断是否为同一概念后再统一。
52. 不要为了追求表达变化而无意义地更换术语、符号或概念名称。

## 14. 输出格式

53. 使用标准 Markdown，标题层级连续、合理，标题必须对应实际知识结构；不要使用无意义的标题堆叠。
54. 输出应适合直接放入 Obsidian，不使用依赖特殊编辑器才能正常显示的非标准 Markdown 写法。
55. **行内公式统一使用 `$...$`**，例如 `$x^2+y^2=z^2$`。
56. **独立公式统一使用 `$$...$$`，并单独成块。** 不要使用 `\(...\)` 或 `\[...\]` 作为常规数学分隔符。
57. LaTeX 命令必须放在正确的数学环境中；数学符号、上下标、分式、根号、矩阵、积分、求和、希腊字母等使用标准 LaTeX 语法。
58. 独立公式使用 `$$` 时，公式内容应完整放在两个 `$$` 之间；不要把普通文字、标题或大段解释塞进数学环境。
59. 不要在公式中混入 Markdown 格式；需要强调、说明或解释时，应放在公式外。
60. 多行推导可使用适合 Obsidian MathJax 的 LaTeX 环境，例如 `aligned`、`cases`、`matrix` 等，并保证整体位于 `$$...$$` 中。
61. 单位、变量和文字说明应根据语义正确处理；不要把普通中文说明无意义地全部写进数学公式。
62. 不滥用独立公式。简单变量、短表达式和正文中的数学符号优先使用行内公式；具有独立表达意义的公式才单独成块。
63. 表格适合用于分类、参数、比较、符号、条件、复杂度等结构化信息；复杂推导、长篇解释和连续论证不要强行制作成表格。
64. 代码必须使用正确的 Markdown 代码块，并标明语言；保证代码格式、缩进和语法清晰。
65. 数学公式、代码、表格和正文之间保持清晰分隔，避免互相嵌套导致 Markdown 或 LaTeX 无法正常解析。

## 15. 长文档一致性

66. 处理长资料时，应始终保持整体覆盖意识，防止前面详细、后面缩水。
67. 检查章节之间的术语、符号、层级、深度和表达是否保持一致。
68. 不得因为篇幅较长就直接省略后半部分、使用“其余类似”或只列标题不展开；只有真正重复且没有新增价值时才可压缩。

## 16. 质量检查

69. 输出前检查：是否覆盖核心知识、是否存在重要遗漏、核心知识是否充分展开、是否有必要补充、是否有明显错误。
70. 检查结构：知识顺序是否合理、前置关系是否完整、分类是否清晰、是否存在明显跳跃。
71. 检查范围：是否超出用户要求、是否遗漏范围内重要内容、是否为了追求全面而无关扩张。
72. 检查冗余：是否存在重复解释、重复公式、无意义扩写、正文与总结机械重复。
73. 检查格式：Markdown、Obsidian、LaTeX、代码、表格、标题层级是否能够正常使用。
74. 最终以用户的原始任务为标准检查：**是否真正完成了用户要求，而不仅仅是生成了一份看起来完整的文档。**

## 17. 停止条件

75. 当核心知识已经覆盖，必要补充已经完成，主要知识关系和必要例题已经处理，边界和特殊情况得到适当说明，并且不存在明显遗漏、重复、范围漂移和格式问题时，任务即完成。
76. 不要因为“还可以继续补充”就无限扩展；只有新增内容能够显著提高当前范围内的理解或使用能力时，才继续加入。
77. **最终目标不是最大化知识数量，而是在明确范围内，以最高的有效信息密度建立正确、完整、清晰、可独立学习的知识体系。**
